## Platform guidance and interpretation

Android requires declared/runtime permission access for protected data; the Weather and audio controls use optional grants. [Android permissions](https://developer.android.com/guide/topics/permissions/overview). Android recommends minimizing permission scope and using coarse location where fine location is unnecessary; Moo requests coarse location and rounds coordinates before weather lookup. [Minimize permission requests](https://developer.android.com/privacy-and-security/minimize-permission-requests). Google Play limits `QUERY_ALL_PACKAGES` to approved core use cases and requires a declaration; package visibility should be kept to the minimum needed for a launcher. [Google Play policy](https://support.google.com/googleplay/android-developer/answer/10158779?hl=en), [Android package visibility](https://developer.android.com/training/package-visibility/declaring). Android recommends repeated Macrobenchmark traces and Baseline Profiles for reliable startup/scroll optimization; this bounded A17 `gfxinfo` check is a regression sample, not a replacement for that method. [Performance measurement](https://developer.android.com/topic/performance/measuring-performance), [Baseline Profiles](https://developer.android.com/topic/performance/baselineprofiles/overview). Emulator timing is not representative of a physical phone. [Android Baseline Profiles codelab](https://developer.android.com/codelabs/android-baseline-profiles-improve).
